# Add props (incl. char limit) to TipTapEditor.vue, mirror BaseInput.vue

## Goal
Give `TipTapEditor.vue` the same prop surface as `BaseInput.vue` (`modelValue`, `label`,
`placeholder`, `maxCharCount`/`minCharCount`, `id`, `rowCount`, `disabled`, `customClass`,
`rules`, `errorMessage`), then wire it into `create-exemption/create.vue` bound to the
existing `formData.details` field.

## Decisions (confirmed with user)
- **Char limit is a hard block**, matching BaseInput's `maxlength` attribute behaviour.
- **Reuse the existing `formData.details` field** (replace the BaseInput on that field),
  rather than adding a new field.

## Constraints discovered
- `@tiptap/extension-placeholder` and `@tiptap/extension-character-count` are NOT installed.
  Placeholder and char limit must be hand-rolled. `@tiptap/pm` IS available.
- `nuxt.config.ts` sets `tiptap: { prefix: 'Tiptap' }`, so `useEditor`, `TiptapStarterKit`
  and `TiptapEditorContent` are auto-provided. Do not import them from `@tiptap/vue-3`.
- Components must not use `template:` string definitions (no Vue runtime compiler in the
  production bundle). Markup belongs in the SFC `<template>`.
- `@nuxt/ui` is NOT a dependency. Icons come from `@heroicons/vue/24/outline`.
- `@tailwindcss/typography` is NOT installed, so `prose` classes do nothing; editor content
  styling lives in a scoped `:deep()` block.

## A. TipTapEditor.vue prop surface
Convert to `<script setup lang="ts">` with `interface Props` + `withDefaults(defineProps<Props>(), {...})`.

| Prop | Default | Notes |
|---|---|---|
| `modelValue` | `''` | HTML string, enables v-model |
| `label` | — | same markup as BaseInput |
| `placeholder` | — | JS-driven (see D) |
| `maxCharCount` | — | hard block |
| `minCharCount` | — | validation |
| `id` | `editor-${random}` | BaseInput pattern |
| `rowCount` | `8` | replaces hardcoded `min-h-48`, drives min-height |
| `disabled` | `false` | `setEditable(false)` + dimmed toolbar |
| `customClass` | `''` | overrides root classes, same as BaseInput |
| `rules` | `() => []` | signature `(value) => true \| string` |
| `errorMessage` | `''` | declared AND rendered (BaseInput declares it but never uses it — do not copy that bug) |

Emits: `update:modelValue`, `error`.
Skipped: `type`, `isTextarea`, `showIcon`, `hideIcon` (password/textarea specific).

## B. v-model two-way sync
- On editor `update`: `emit('update:modelValue', editor.getHTML())`.
- `watch(() => props.modelValue)`: `editor.commands.setContent(val, { emitUpdate: false })`
  guarded by an internal-update flag so external writes do not echo back and reset the cursor.

## C. Character counting + hard limit
- `charCount = editor.getText().length` — plain text, not HTML, so tags do not inflate it.
- `charCounterText` reuses BaseInput's exact three-branch format:
  - both: `${n} / ${max} character (min ${min})`
  - max only: `${n} / ${max} character`
  - min only: `${n} (min: ${min})`
- Enforcement: `@tiptap/pm/state` `Plugin` with `filterTransaction` — reject any transaction
  whose resulting doc text length exceeds `maxCharCount`, but always allow transactions that
  shrink the doc, so undo / delete / selection can never deadlock. Also caps oversized pastes.
- Counter turns red as the limit is approached.

## D. Placeholder without the extension
`isEmpty` computed from the `update` / `selectionUpdate` events toggles a class on the content
wrapper; an absolutely-positioned Tailwind-styled `<div>` renders the placeholder text.
CSS `:empty` cannot be used — ProseMirror emits `<p><br class="ProseMirror-trailingBreak">`.

## E. Validation + footer
- `validate()` on editor update and on blur, same order as BaseInput: `rules` loop first,
  then `minCharCount` → `Minimum ${min} characters required.`
- Emits `error` with the message, `''` when valid.
- Footer mirrors BaseInput: error left, char counter right.

## F. create.vue changes (reuse formData.details)
1. Replace the `BaseInput` block (lines 1096–1099) with:
   ```vue
   <TipTapEditor v-model="formData.details"
     label="Additional Comment/Detailed Info"
     placeholder="Explain the reason for your exemption request..."
     :maxCharCount="5000" :minCharCount="10" :rowCount="5"
     :errorMessage="errors.details" />
   ```
   Keep the red asterisk in the label. Note `:error` → `:errorMessage`; `:error` was never a
   declared BaseInput prop and was silently falling through as a stray attribute.
2. Add a `detailsText` computed (strip tags → decode entities → collapse whitespace).
   `details` is now HTML, so the length checks at lines 475, 518 and 531 would count markup.
   All three switch to `detailsText`.
3. Fix the pending-restore preview at line 1385 — `{{ }}` would print raw `<p>` tags.
   Render `detailsText` instead of using `v-html`, keeping the XSS surface closed.
4. No change needed to the snapshot (142, 167, 603, 734), submit (592, 712) or restore
   (919, 954) paths — field name is unchanged, they simply now carry HTML.
   `Details` is `string?` on the DTOs, so it stores fine.

## Out of scope (flagged to user)
Once `details` is HTML, every other screen rendering it (view/edit/detail pages) must
sanitize or strip. `v-html` on unsanitized stored HTML is stored XSS. Left untouched
unless requested.
